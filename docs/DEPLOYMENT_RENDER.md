# Render Deployment Guide: PG Owner Backend

This guide details how to deploy `pg-owner-backend` to **Render** as a production-grade Web Service.

---

## 1. Prerequisites

1. A **Render** account at [dashboard.render.com](https://dashboard.render.com).
2. Access to your MongoDB Atlas cluster ([cloud.mongodb.com](https://cloud.mongodb.com)):
   - **Network Access**: Add `0.0.0.0/0` (Allow Access from Anywhere) under *Network Access* -> *IP Access List* in MongoDB Atlas. Cloud providers like Render assign dynamic IP addresses to free and standard instances.

---

## 2. Option A: Blueprint Deployment (Fastest & Recommended)

This repository includes a [`render.yaml`](../render.yaml) blueprint specification that preconfigures the build, start, health check, and environment variables.

1. Navigate to the [Render Dashboard](https://dashboard.render.com).
2. Click **New +** in the top navigation bar and select **Blueprint**.
3. Connect your GitHub repository: `https://github.com/vikasraj2219/pg-owner-backend`.
4. Render will parse `render.yaml` automatically:
   - **Service Name**: `pg-owner-backend`
   - **Environment**: `Node`
   - **Region**: `Singapore` (lowest latency for India)
   - **Plan**: `Free`
   - **Build Command**: `npm install --include=dev && npm run build`
   - **Start Command**: `npm start`
   - **Health Check**: `/api/health`
5. Under **Environment Variables**:
   - `MONGODB_URI`: Paste your MongoDB Atlas connection string:
     ```
     mongodb+srv://<username>:<password>@cluster0.uyydgfg.mongodb.net/hostel_pg_management?retryWrites=true&w=majority
     ```
   - `JWT_SECRET` and `INTERNAL_CRON_SECRET` will be cryptographically auto-generated by Render.
6. Click **Apply**. Render will trigger the initial build and deploy.

---

## 3. Option B: Manual Web Service Deployment

If deploying manually without Blueprint:

1. In Render Dashboard, click **New +** -> **Web Service**.
2. Select **Build and deploy from a Git repository** and connect `pg-owner-backend`.
3. Fill in the service configuration:
   - **Name**: `pg-owner-backend`
   - **Region**: `Singapore`
   - **Branch**: `main`
   - **Root Directory**: *(leave blank)*
   - **Runtime**: `Node`
   - **Build Command**: `npm install --include=dev && npm run build`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free`
4. Expand **Advanced** -> **Health Check Path**:
   - Set to `/api/health`
5. Under **Environment Variables**, add:

| Key | Recommended Value | Notes |
| :--- | :--- | :--- |
| `NODE_ENV` | `production` | Enables production optimizations |
| `API_PREFIX` | `/api` | Base path for all routes |
| `MONGODB_URI` | `mongodb+srv://...` | Your MongoDB Atlas connection URI |
| `JWT_SECRET` | *(Random 32+ character string)* | Token signing secret |
| `JWT_EXPIRES_IN` | `30d` | JWT lifespan |
| `CLIENT_URL` | `*` | Allowed CORS origin |
| `INTERNAL_CRON_SECRET` | *(Random 16+ character string)* | Secret for triggering internal tasks |

6. Click **Create Web Service**.

---

## 4. Post-Deployment Verification

Once Render finishes deploying (indicated by a green `Live` status badge):

1. **Verify Health Endpoint**:
   ```bash
   curl -s https://<your-service-name>.onrender.com/api/health
   ```
   Expected response:
   ```json
   {
     "success": true,
     "data": {
       "status": "ok",
       "environment": "production",
       "database": { "state": "connected", "connected": true },
       "version": "0.1.0"
     }
   }
   ```

2. **Connect the Mobile App (`pg-owner-mobile`)**:
   Update `/Users/zdofice02/Documents/GitHub/pg-owner-mobile/.env`:
   ```env
   EXPO_PUBLIC_API_URL=https://<your-service-name>.onrender.com/api
   ```
   Now the mobile application on Expo Go, physical iOS/Android devices, and Web will communicate with the live Render cloud backend without requiring local network or IP configuration.

> [!NOTE]
> On Render's Free tier, services spin down after 15 minutes of inactivity. When a new request arrives, a cold start takes approximately 30–50 seconds.
